## Task group
IntelliJ-EmmyLua LuaDoc/EmmyLua annotation generation and completion behavior.

## Scope of applicability
Use when modifying generated `---@field` annotations, LuaDoc field completion, tutorials/templates, or inspection tests in the IntelliJ-EmmyLua workspace.

## User preference / correction evidence
User explicitly corrected that the prompt/generated annotation was wrong: `public` should not be added (`提示的有问题，应该不加public`).

## Stable project decision
Newly generated LuaDoc field annotations should be `---@field name type`, not `---@field public name type`.
Do not remove parsing compatibility for historical/manual `---@field public ...` or `protected` forms; only stop generating/promoting them.

## Files and entry points
- `src/main/java/com/tang/intellij/lua/comment/LuaCommentUtil.kt`
  - `insertFieldAnnotation(...)` now emits `---@field $fieldName $typeText`.
  - `insertFieldTemplate(...)` now starts template text as `---@field $fieldName `.
- `src/main/java/com/tang/intellij/lua/editor/completion/LuaDocCompletionContributor.kt`
  - Removed `SHOW_ACCESS_MODIFIER` completion registration that suggested `protected` and `public` immediately after `@field`.
  - Removed the `SHOW_ACCESS_MODIFIER` pattern.
- `src/main/resources/fileTemplates/internal/Tutorial.lua.ft`
  - Tutorial example changed from `---@field public age number age value` to `---@field age number age value`.
- `src/test/kotlin/com/tang/intellij/test/inspections/GeneratedEmmyAnnotationInspectionTest.kt`
  - Expected generated field annotation changed to omit `public`.
  - A legacy input `---@field public existing string` was intentionally kept to verify compatibility/insertion around old annotations.

## Reusable validation
Run targeted test on Windows wrapper:
`./gradlew.bat test --tests com.tang.intellij.test.inspections.GeneratedEmmyAnnotationInspectionTest`
Observed result: `BUILD SUCCESSFUL`.

## Guardrails / failure avoidance
- Search for `field public` under `src/main/**/*`; after the fix there should be no main-source generation path still producing it.
- Do not delete parser/PSI support for visibility; `LuaDocPsiImplUtil.kt`/LuaDoc parsing still may expose `visibility` for backward compatibility.
- Completion tests may still include old `public/protected` formats as parsing/compatibility cases; do not blindly rewrite all test fixtures.
