### Task group
LuaDoc / EmmyLua inspection quick-fix enhancement for missing self field annotations.

### Scope of applicability
Affects inspection-generated fixes for `self.xxx` field-type warnings in:
- `src/main/java/com/tang/intellij/lua/codeInsight/inspection/GeneratedEmmyAnnotationInspections.kt`
- `src/main/java/com/tang/intellij/lua/comment/LuaCommentUtil.kt`
- `src/main/java/com/tang/intellij/lua/codeInsight/template/macro/SuggestTypeMacro.kt`
- `src/test/kotlin/com/tang/intellij/test/inspections/GeneratedEmmyAnnotationInspectionTest.kt`

### Reusable implementation decisions
- Keep the existing field annotation fix and add a second quick-fix instead of replacing the old one.
- New quick-fix family text: `Generate type annotation`.
- When the inspection sees a `self` field issue, register two fixes if possible:
  - `Generate field annotation` for class-level `---@field`
  - `Generate type annotation` for statement-level `---@type`
- `Generate type annotation` should insert `---@type ...` before the current assignment statement.
- Derive the default type from the right-hand-side expression of the assignment (`self.a = b` -> infer from `b`), falling back to `table` when unavailable.

### Helper / API clues
- `LuaCommentUtil.insertEditableTypeTag(commentOwner, editor, defaultType)` is the reusable entry point for editable `---@type` insertion.
- `SuggestTypeMacro` was extended to accept `defaultType` and must preserve lookup behavior.
- Important: the template engine in tests/IDE can auto-select the first lookup item, so the default type must be placed first in lookup items to avoid being overridden.
- Relevant PSI helpers used in the fix:
  - `LuaAssignStat.getIndexFor(...)`
  - `valueExprList?.getExprAt(index)`
  - `guessType(context)`
  - `LuaAnnotationSupport.getTypeText(type)`

### Failure symptom -> cause -> fix chain
- Symptom: `---@type` quick-fix generated `string` or `stringnumber` in tests.
- Cause: live template / lookup selected the first completion item and appended typed input; default text was not stable.
- Fix: make `SuggestTypeMacro(defaultType)` return / surface the provided default type first, so the template starts with the expected text while still allowing completion.
- Also removed an incorrect extra `checkResultByFile("main.lua")` inside `checkByDirectory`; the helper already compares the temp file tree.
